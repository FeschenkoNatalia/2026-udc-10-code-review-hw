# Task E (бонус) — шлях 3: два рев'юери

**Чому шлях 3:** шлях 1 потребує публічного форку і секрету з ключем моделі; шлях 2 міряє лише наш рев'юер.
Шлях 3 відповідає на питання команди: чи потрібен свій стандарт, чи досить загального рев'ю-скілу?

## Як порівнювали

- **Рев'юер 1** — наш `/review-pr` зі стандартом команди: v1 (Task B, до тюнінгу) і v2 (Task C, після тюнінгу).
- **Рев'юер 2** — скіл [`review-task`](https://github.com/koldovsky/skill-review-task) (коміт `6a3b00e`, без змін).
- **Умови однакові:** `review/run-review.mjs`, `claude-opus-5-5`, нова сесія на кожен PR, лише читання файлів.
- **Різниця — інструкції й субагент.** Обидва бачать код і домовленості команди (`docs/team-conventions.md`).
  Рев'юер 1 отримує ще наш стандарт (`docs/review-standard.md`: правила, що з них блокує злиття, як перевіряти),
  рев'юер 2 — замість нього загальні критерії скілу (`CRITERIA.md`). Скіл до того ж передає рев'ю субагенту
  (інструмент `Agent`, теж лише читання): сесія і субагент на кожен PR — частина його вартості.
- **Підрахунок** — як у `docs/review-scorecard.md`. Звіти скілу — `review-runs/pr-N.review-task.md`.

```bash
git clone https://github.com/koldovsky/skill-review-task.git ~/.claude/skills/review-task
git -C ~/.claude/skills/review-task checkout 6a3b00e
node review/run-review.mjs <N> --reviewer review-task
```

## Висновок

**Знаходять однаково, блокують по-різному.** Що блокує злиття, рев'юеру каже наш стандарт.

- **Знаходження:** скіл знайшов 15 із 15 дефектів без хибних тривог — як v2 і краще за v1 (14 із 15, 3 хибні).
- **Блокування:** без нашого стандарту порушення домовленостей для скілу — лише Warning, тож він блокує 6 дефектів
  із 15, наш рев'юер — усі 15.
- **Ціна:** скіл у ≈ 2.5 раза дорожчий і повільніший, звіти в ≈ 2.7 раза довші.

**Рішення:**

1. У CI лишаємо `/review-pr`: дешевший і блокує за правилами команди.
2. Зі скілу беремо поріг впевненості й перевірку знахідок KEEP / WEAKEN / DROP — менше хибних тривог.
3. PR про доступ, гроші й дані рев'юять обидва.

**Обмеження:** один прогін на PR; 15 дефектів — мала вибірка; v2 налаштовано на цій самій черзі, тож чесне
порівняння «з коробки» — v1 проти скілу.
