## PR-1: «Сторінкування для списку позик»
**Вердикт:** REQUEST_CHANGES
`listLoansPage` рахує сторінки з одиниці, а зсув — з нуля, тому перша сторінка ніколи не повертається. Розмір сторінки нічим не обмежений, тест не перевіряє `items`, а в CHANGELOG немає запису про нову експортовану функцію.

### F1 — app/src/loans.js → listLoansPage — зсув на сторінку: перша сторінка недосяжна
- R16 · блокує: так · high
- `review-queue/pr-1/change.diff:12`
  ```text
  +  const start = page * pageSize;
  ```
- Типове значення `page = 1` (рядок 10) означає сторінки з одиниці, а `start = page * pageSize` рахує зсув так, ніби вони з нуля. Вхід: `createDb()`, `iryna`, `{}` (тобто `page: 1, pageSize: 20`). Очікувано: `items` — позики з id 1–7. Фактично: `all.slice(20, 40)` дає `[]` при `total: 7`. На 3 000 рядках перша сторінка показує рядки 21–40, а рядки 1–20 не видно на жодній сторінці. Виправлення: `const start = (page - 1) * pageSize;`.

### F2 — app/src/loans.js → listLoansPage — розмір і номер сторінки не перевірені й не обмежені
- R7 · блокує: так · high
- `review-queue/pr-1/change.diff:10`
  ```text
  +export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
  ```
- `pageSize` і `page` йдуть у `slice` як є, без перевірки й верхньої межі. Вхід: `{ pageSize: 1000000 }`. Очікувано: відмова або обрізання до максимуму. Фактично: на 3 000+ рядках функція віддає весь список, тобто той самий обсяг, через який PR і писали. Від'ємний чи дробовий `pageSize` або `page` теж дають довільний зріз: наприклад, `{ page: 1, pageSize: -5 }` повертає `slice(-5, -10)`, тобто `[]`. Виправлення: перевіряти, що `page` і `pageSize` — додатні цілі, і обмежити `pageSize` сталою на зразок `MAX_PAGE_SIZE`.
